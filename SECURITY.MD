# Security Policy

## Supported Versions

This project is actively maintained on the `main` branch.

| Version | Supported |
| ------- | --------- |
| main    | Yes       |
| older commits/releases | No |

## Reporting a Vulnerability

If you discover a security vulnerability, please report it privately.

1. Do not open a public issue.
2. Use GitHub Security Advisories (preferred) if available for this repository.
3. If advisories are not available, contact the repository maintainers privately.

When reporting, include as much detail as possible:
- A clear description of the issue and impact.
- Steps to reproduce.
- A proof of concept, if available.
- Affected files, endpoints, or components.
- Suggested remediation, if known.

## Response Process

The maintainers will aim to:
- Acknowledge receipt within 3 business days.
- Provide an initial assessment within 7 business days.
- Share a remediation plan and timeline after validation.

## Disclosure Policy

Please allow maintainers reasonable time to investigate and remediate before public disclosure.
Coordinated disclosure helps protect users and downstream systems.

## Security Best Practices for Contributors

- Keep dependencies up to date.
- Avoid committing secrets or credentials.
- Validate all input and handle errors safely.
- Follow least-privilege principles for configuration and access.
